Step 1 — Setup

Prerequisites

1
Install dependencies

Run once after cloning the repo.

npm install
npx playwright install chromium
2
Create storage-state login files

Three saved browser sessions — one per role. Run the codegen command below and log in as the matching user, then close the browser.

Generate GBO session (repeat for cuo.json and uw.json)
npx playwright codegen \
  --save-storage=storage-states/gbo.json \
  https://your-app-url.com
⚠

Add storage-states/ to .gitignore — these files contain session tokens.

3
Set the base URL

Create .env.qa (and optionally .env.staging) in the project root.

.env.qa
BASE_URL=https://your-allianz-app-url.com
4
Bootstrap the Excel form manifest

Run once to create test-data/form-manifest.xlsx with the correct 15-column schema and sample rows.

npx tsx scripts/generate-mock-manifest.ts

Open the file, delete the sample rows, and add your real forms. See Excel Schema below for the column guide.

5
Generate mock PDFs from the manifest

Reads every form in the manifest and auto-generates template + preview PDFs. No manual PDF authoring needed.

npx tsx scripts/generate-mock-pdfs.ts

Mock Run

How to Do a Mock Run

Mock mode runs entirely offline — no browser session, no live app, no PDF viewer needed. It compares local PDF files only. Use this to validate the manifest, PDFs, and test logic today.

✦ Mock Mode
  • No browser required for PDF checks
  • Reads local template + preview PDFs
  • Checks field values and required statements
  • Works before the app PDF viewer exists
  • Triggered by USE_MOCK_PDF=true
✦ Real Mode
  • Full browser + live app required
  • Captures PDF bytes from in-app viewer
  • Validates against live UI field values
  • Checks required statements from manifest
  • No flag needed — real mode is the default

1 — Run offline PDF unit tests (no app needed)

npx playwright test tests/mock/mock-pdf-comparison.spec.ts

Validates that all {{variables}} in templates resolve, field values appear in preview PDFs, and required statements are present. No app connection needed. 14 tests.

2 — Run the full policy lifecycle in mock PDF mode

Mac / Linux
USE_MOCK_PDF=true BASE_URL=https://your-app-url.com \
  npx playwright test tests/lifecycle/policy-lifecycle.spec.ts --workers=1
Windows — Command Prompt
set USE_MOCK_PDF=true
set BASE_URL=https://your-app-url.com
npx playwright test tests/lifecycle/policy-lifecycle.spec.ts --workers=1
ℹ

Always use --workers=1 for the lifecycle spec. The 17 tests are serial and share submission state across the run.

3 — Run forms validation in mock PDF mode

All products from manifest (no browser)
USE_MOCK_PDF=true \
  npx playwright test tests/forms/forms-validation.spec.ts
Filter to one product / transaction
PRODUCT="Builder's Risk" TRANSACTION=Quote USE_MOCK_PDF=true \
  npx playwright test tests/forms/forms-validation.spec.ts
⚑

The forms validation test is data-driven — it reads every product and formset from the manifest automatically. Adding new forms to the Excel = new tests run. No code changes ever needed here.

Real Mode

How to Run Once Original Functionality Is Available

When the in-app PDF viewer is live, switching from mock to real is a one-line change — no code modifications, only env vars.

1
Remove USE_MOCK_PDF=true from your env file

Open .env.qa and delete (or set to false) the flag. That's the only change needed.

.env.qa — before
BASE_URL=https://your-app-url.com
USE_MOCK_PDF=true   ← remove this line
.env.qa — after
BASE_URL=https://your-app-url.com
2
Run the full lifecycle

FormsPage automatically switches to PdfValidator.captureAndValidate(), which opens the new-tab PDF viewer and validates live values.

BASE_URL=https://your-app-url.com \
  npx playwright test tests/lifecycle/policy-lifecycle.spec.ts --workers=1
3
Run forms validation against a live submission

Provide the URL of an existing open submission. The test navigates to its Forms tab and validates all formsets.

BASE_URL=https://your-app-url.com \
SUBMISSION_URL=https://your-app-url.com/submissions/12345 \
  npx playwright test tests/forms/forms-validation.spec.ts --workers=1
✓

The mock PDFs remain in test-data/mock-pdfs/ after switching to real mode. The offline unit tests (tests/mock/mock-pdf-comparison.spec.ts) continue to use them — nothing needs to be deleted.

What the validator checks in real mode

  • Form number (Unqork Form Number) appears in the PDF
  • Form name appears in the PDF
  • Each field label + its live UI value appear together in the PDF
  • Required statements (all Type=statement rows from the manifest) appear verbatim in the PDF

Troubleshooting

Troubleshooting

  • !
    storage-state file not found
    Run your login script to generate storage-states/gbo.json and storage-states/cuo.json.
  • !
    No BASE_URL provided
    Set BASE_URL in .env.qa or export it in your shell.
  • !
    Mock PDF(s) not found for UQ-XXX
    You added rows to the manifest but haven't regenerated PDFs. Run npx tsx scripts/generate-mock-pdfs.ts.
  • !
    Forms validation skipped with warning
    Either PDF_VALIDATION_ENABLED=false is set, or the manifest has no matching rows. Verify the sheet name is exactly Forms.
  • !
    No matching scenarios in manifest for current env filters
    The PRODUCT / SUB_SEGMENT / TRANSACTION env vars don't match any rows. Run without filters first to see what's available.
  • !
    Submission context is stale / deleted submission
    Delete test-data/contexts/policy-lifecycle.json and re-run from test 01.
  • !
    Required statement check fails but text seems present
    The statement text must match character-for-character what's in the Excel. PDF line-wrap is handled automatically, but extra spaces or punctuation differences will fail. Copy the exact text from the PDF into the manifest.
